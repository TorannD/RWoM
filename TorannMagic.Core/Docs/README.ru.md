# RWoM Core для RimWorld 1.7

**Для игры.** Включите Harmony, затем RWoM Core (Ability Framework), основной мод A RimWorld of Magic (Continued) и классовое дополнение. После замены DLL перезапустите игру. Сам Core предоставляет реестр способностей и работу с ресурсами. Классы, гримуар и получение заклинаний реализованы в основном моде. Основной мод допускает запуск без Core. Для дополнения, использующего DLL или XML-типы Core, Core обязателен.

**Для автора заклинания.** Придумайте постоянный ID со своим префиксом, например myaddon.glassward. Включите [расширение](Examples/SpellIdentity.xml.txt) в Def способности, добавьте зависимость huginn.rwom.core в About.xml и проверьте после загрузки Def, что поиск возвращает нужную способность. При переименовании Def сохраните прежний ID. Опубликованный ID становится частью контракта с сохранениями пользователей. У разных рангов сейчас должны быть разные ID, если нужно получать конкретный Def.

**Диагностика.** Если XML сообщает о неизвестном типе, проверьте порядок модов и полное имя расширения. Если ID не разрешился, проверьте регистр, активность дополнения и первую ошибку загрузки. При совпадении ID найдите в логе имена конфликтующих Def. Отсутствие потребности в мане у пешки допустимо. Не выдавайте класс автоматически по результату такого запроса.

## Как подключить дополнение

1. Если ваше дополнение использует типы из TorannMagic.Core.dll напрямую, добавьте зависимость huginn.rwom.core в modDependencies. В csproj укажите ссылку на установленную DLL с Private=false. В комплект дополнения включайте только собственную DLL.
2. Для необязательной XML-интеграции добавьте атрибут MayRequire="huginn.rwom.core" на элемент li с расширением. Необязательная C#-интеграция также должна загружать код с типами Core только при наличии зависимости.
3. Для примера скачивать отдельный SDK не требуется. В папке Examples уже лежат [готовый проект](Examples/AddonExample.csproj), [код проверки доступности](Examples/GlassWard.cs) и XML-фрагмент. Скопируйте папку в рабочий каталог и выполните команду сборки из [API.md](API.md).

## Частые вопросы

**Как узнать, изучила ли пешка заклинание?** Успешный TryResolve означает, что в текущем наборе модов есть соответствующий Def. Вызовите PawnSpellKnowledge.Read. Статус Available и флаг Learned означают, что пешка изучила доступное заклинание. При MissingDefinition снимок содержит сохранённые ранги отсутствующего заклинания. PendingImport означает, что прежняя прокачка ещё восстанавливается. Дождитесь штатного тика пешки. Доступность самого каста проверяется отдельно.

**Почему в игре 100 маны, а API возвращает другую величину?** Метод читает внутренние единицы потребности. Например, для цены в 10% возьмите MaxLevel, умноженный на 0,1. Проверять наличие маны можно при отрисовке кнопки, списывать — один раз при подтверждённом действии. При штатном касте RWoM уже оплачивает способность.

**Что произойдёт при отключении дополнения?** Идентификатор может перестать разрешаться. Храните ID в сохранении и проверяйте его после загрузки Def. Когда игрок вернёт дополнение, привязка снова станет возможной. Для проверки используйте копию сейва.

**Как сообщить о проблеме?** Приложите версию игры, версии модов, порядок загрузки, точный ID, имя Def, результат на новой игре и первую относящуюся к ошибке запись Player.log. Для ошибки цены укажите баланс до и после действия и число вызовов оплаты.
Для гибридов PawnDisciplines.TryRead возвращает отдельную строку на каждую активную дисциплину со своей ступенью. У классических пешек и классов Kure ступень Classic. AbilityCasting.Check проверяет ручной или автоматический каст без постановки задания. Ответ UnsupportedAbility оставляет решение владельцу сторонней способности.
